CANDIDATO COMPLETO
------------------

Antes de tocar main se crea:

E:\MVP\iRec-worktrees\v0.2.0
  -> integration/v0.2.0

Ese worktree recibe, por Git merge:

main
  + feat/backend
  + feat/frontend
  + docs/project
  = integration/v0.2.0

NO integrar copiando/extrayendo ZIPs entre worktrees. Los ZIPs son artefactos
de transporte/revisión; la integración real se hace con Git.

CREAR EL CANDIDATO (Git Bash)
-----------------------------

cd /e/MVP/iRec
git fetch origin --prune
git switch main
git pull --ff-only origin main

git worktree add -b integration/v0.2.0 ../iRec-worktrees/v0.2.0 main
cd ../iRec-worktrees/v0.2.0

git merge --no-ff feat/backend  -m "merge(v0.2.0): integrate identity backend"
git merge --no-ff feat/frontend -m "merge(v0.2.0): integrate identity frontend"
git merge --no-ff docs/project  -m "merge(v0.2.0): integrate project docs"

git status
git push -u origin integration/v0.2.0

OBJETIVO DEL CANDIDATO
----------------------

  docker compose up --build -d

El compose full-stack levantará:

  irec-web
  irec-api
  irec-migrate
  irec-postgres
  irec-redis
  irec-mailpit

modo de desarrollo híbrido.
